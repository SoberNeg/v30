# Перенос исправлений Windows-сборки на новую версию автора

Автор присылает очередной `LED_Screen_Designer_vXX_YY.py`, сделанный от своей ветки
(без исправлений сборки). Скрипт накладывает их и проверяет результат:

    python3 tools/port_fixes.py <исходник_автора.py> LED_Screen_Designer_vXX_YY_1.py XX.YY

Что переносится (`my_fixes.patch` = diff v30.72 → v30.74 сборки + пост-обработка в скрипте):
1. Стартовое окно РЖД/МЦД открывается через `after(150)` после старта mainloop
   (иначе на Windows окно невидимо, главное окно заблокировано) + `startup_dialog_error.log`.
2. Тема «Светлая / Тёмная» (префикс `_uitheme_`, переключатель в верхней панели,
   `%APPDATA%\LED Screen Designer\ui_settings.json`).
3. Заливка статических строк «Комплектующих» (`static_gray_1..4`, сохраняется при
   объединении, раздаётся заново после сортировки).
4. Стыковки: V30.90 (сортировка по столбцам, плашки «Статус/УПД» не перекрашиваются),
   V30.94 (центрирование вкладок после смены темы), тёмная тема — «бледный» текст
   остаётся бледнее основного (пары цветов журнала V40.25).

Скрипт печатает `ALL_OK` и список удалённых строк (норма — 17: заголовок версии,
старый запуск стартового окна, старые static_gray, две строки merge).
Дальше: заменить файл в корне, `sed` старого тега на новый в `.github/workflows/*.yml`
и README, коммит → сборка `build-windows.yml` (smoke-тест: главное окно + «Выбор проекта»),
вручную `ui-screenshots.yml` с `inputs[src]=<файл>` → скриншоты/отчёт в ветке `ci-screenshots`.
